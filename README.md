# 通用角色记忆 — 0.4.0

当前版本已改为通用角色插件。下文旧版本章节保留历史说明；本节的 0.4.0 行为优先。

## 0.4.0：通用角色与历史继承

记忆规则、上下文标题、工具说明、管理页和导出文件名改为通用说法。绑定可携带 characterName 显示元数据，改显示名仍使用原人格标识、聊天、记忆、人物和情绪；旧调用者未传名称时保留已有元数据。新旧持久数据格式兼容。

插件包名、nia_* 工具名、服务/路由/存储目录和默认数据标识保持兼容。它们是内部标识，不代表角色姓名。换角色继续继承原数据时，保持原 personaId，不复制或重绑会话，也不改写旧事件中的名字。更换角色卡时，手动同步情绪设置的人格摘要；本插件不会自动覆盖用户的角色卡和摘要。

此版本不提供同时多角色运行或切换时隔离数据。136 项回归通过；设置页在隔离环境实际验证保存、刷新与旧摘要保留。更新后需重启 DSH 后端。


独立插件，不修改 dsh-fish-memory。与 dsh-nia-mood 0.4.0、dsh-nia-qq 0.4.0 通过 Cordis 服务联动。
状态：已完成本地测试和隔离浏览器交互验证；尚未完成正式 DSH 窗口及真实模型、QQ 往返验证。使用本地链接安装时，更新源码后需重新加载插件或重启 DSH。

## 设置界面

面板分为“记忆库”“人物”“会话接入”“管理与备份”。QQ 联动自动接入；桌面会话在“会话接入”选择已打开的会话，填写人物标识后点击“保存会话绑定”。
启停、回收、恢复和信息范围操作会立即生效并显示结果；它们不依赖全局保存按钮。原始事件与共享情绪 JSON 收入管理页诊断详情。

## 用法

先安装本套件三个包并重新加载 DSH。在“妮娅 · QQ”启用“联动妮娅记忆与情绪”。同一 personaId 的群聊和私聊共享人格经历，聊天全文仍各自保留。
设置里的“你的 QQ 号”用于标记用户身份；不按昵称猜测谁是用户。
桌面会话可在“妮娅的记忆”中手动绑定。要与 QQ 识别为同一个人，填写相同人物 ID：`qq:机器人账号:用户QQ号`。此关联由使用者明确指定。
桌面默认预演，正式会话需另开窗口绑定；已绑定会话不能静默切换人格、聊天或预演属性。

## 数据与召回

数据位于 `$DSH_HOME/nia-memory/state.json`；未设置 DSH_HOME 时是用户目录下 `.dsh/nia-memory/state.json`。
本版是结构化 JSON 文件，不是 SQLite，也没有向量数据库或外部嵌入服务。
唯一写者锁、同步事务、版本号、写临时文件后原子替换、上一版 `.bak` 备份用于避免丢写。损坏文件不会自动清空。
本地搜索采用通用中文词典最长匹配、英文词、记忆检索词，以及当前可见库的词频证据；结合人物、重要度、鲜活度和记忆情绪强度排序。默认自动 6 条、正文 2400 字，设置页可调；主动检索最多 12 条。
已补回词典分词、自动和批量检索词扩展；不使用向量数据库。提示背景还包含近期来源片段和人物信息。
日常事件的召回优先级随时间下降，原记录不会因此删除。软删除与纠错保留旧记录和证据。

长期记忆由 Agent 使用工具选择写入，不强制每轮保存。可信入站事件单独记录，不等于每条消息都成为长期记忆。
人物用稳定账号 ID 区分；同名不同人不会合并。自己的发现、探索、失败、兴趣和项目可以保存。
状态分为 reported（自述）、observed（工具观察）、inferred（推测）、planned、attempted、completed、failed、cancelled、fictional（虚构情节）。
聊天自述不能直接作为 observed/completed 的证明；失败回执不能证明完成。成功工具回执也不保证整个项目完成，需要 Agent 根据内容正确提炼。

## 工具

- `nia_remember`：带主体和 evidenceIds 写入记忆；可用 attribute + replaces 明确纠正同一人的同一属性。
- `nia_recall`：按话题和人物主动检索。
- `nia_recent`：按聊天、人物、关键词与时间读取原始近期事件和发送回执；最多 30 条、合计 12000 字。遵守 private 来源聊天限制与预演隔离；没有长期摘要也可以查到已录入事件。空结果不能证明事情没有发生。
- `nia_people`：列出稳定身份、名字和自选称呼。
- `nia_observations`：按真实工具 callId 提取执行回执作为自身经历来源；不接受凭空捏造的回执，跳过内部 nia 工具。原始回执默认 private。

## 信息范围

- shared：可转述的背景。
- internal：内部知情；Agent 根据交流对象和原语境决定如何表达，不自动复制原文。
- private：来源聊天以外不能检索或通过事件接口携带；同源摘要也会一起限制。

这些过滤作用于本插件提供的记录和事件引用；不能抹除已进入 DSH 历史的文本，也不是所有其他插件或模型自由文本的完整信息流隔离系统。
“移入回收站”隐藏长期记忆摘要，原事件及既有 DSH 聊天历史保留；不等同彻底遗忘或擦除聊天。
预演事件单独标记，正式会话不读取预演记录；QQ 联动还使用独立 DSH 历史。

## 管理与迁移

面板提供启停、检索记录、回收/恢复、限制到原聊天、查看事件与共享情绪、导出 JSON 备份。每次写入保留上一版 .bak，并保留最近 14 个备份日的每日首份状态（北京时间分日）。
导出内容含私人经历，请按自己的资料保存。恢复需停掉 DSH 后用备份替换状态文件；本版没有自动导入旧 fish-memory。
正常停机释放 writer.lock。若异常退出留下锁，先确认所有 DSH 进程均已停止，再移走锁文件；不要在运行中强制抢锁。
换电脑时要同时迁移本插件数据、QQ 配置/映射、情绪配置和 DSH 原生会话文件；只复制本插件不会带走完整聊天上下文。
备份后可在新机调整 QQ 连接、模型提供方、人格文件和工作目录路径。正式数据不要用测试样例覆盖。

## 局限

JSON 存储适合当前单机初版，每次提交会复制并写整份状态；大量长期群消息需要后续 SQLite/分段归档升级。
不读取私人的微信/QQ 历史，不自动导入旧插件数据，不提供空闲定时活动。
本地单元与模拟宿主测试使用 `node --test --test-isolation=none test/*.test.mjs`。


## 0.3.3 功能补齐

- 记忆库：选择记录、编辑正文、人物及来源查看、回收恢复。人工新增/修改一律作为 reported，记录独立人工来源，不伪装工具观察；编辑保留人物、来源聊天、预演状态，不能扩大私密范围。
- 导入与整理：选择管理会话；扫描本地文档或粘贴文本，选择候选与人物，预览后应用。支持 .md/.markdown/.txt/.text/.log/.rst/.org，下探两层、最多 50 文件/3 MB、单文件 1 MB、500 候选。忽略子目录链接。已回收导入记录也参与去重，不会自动复活。
- 批量：检索词扩展、忠实摘要提炼、明确绝对日期补齐、属性键补齐、长期稳定属性重新判断、相似重复记录合并。单批 100 条，先预览、可勾选应用；合并限相同人物、来源聊天、范围、类型、状态和属性。相似不是同一件事的证明，需检查。
- 模型任务：使用所选已打开管理会话的模型，串行、每条 45 秒超时、进度/取消/失败提示、重试未完成部分；完成部分有独立预览。预览和任务进度仅保留在本次插件运行中，退出前需应用或下载。已应用批次与撤销记录持久保存。
- 自动扩词默认开启：Agent 写入新的长期记忆后，后台调用模型补检索词；不开启无限回填。关闭开关后不再应用未完成的自动扩词。失败可在整理页查看并手动重试。原始消息入库不触发扩词。
- 从历史会话生成档案：显式选择来源会话，读取聊天文字、排除推理与系统注入。QQ 已绑定聊天优先使用记忆库中的可信入站事件和确认发送回执；其余读取所选 DSH 会话快照或本地 Zstd 历史。每批 7000 字、最多 100 批，保留人物/发言角色；生成后可下载 Markdown 或转入导入预览，不直接当作已证实经历。需要读取磁盘 Zstd 时依赖宿主 Node 支持；不支持时先在 DSH 打开会话。
- 召回诊断：查看最近自动召回或按给定问法测试，列出分词、命中、分数、鲜活度、未选原因。诊断先按身份与范围过滤，不泄露其他会话私密记录。最近召回轨迹只保存在当前运行内存中。
- 参数：半衰期、证据门槛、条数/字数、稳定事实占位、排序权重、自动扩词、自主写入日配额。日配额默认 0（不限），与人工导入分开；重要度不等于永久记忆，稳定属性可独立调整。记忆情绪强度为可选 0–1 元数据，不等于实时心情。
- 应用/撤销比较原记录快照：存在后续改动则整批拒绝，避免旧结果吞掉新记忆；导入撤销仅隐藏摘要，原始来源仍保留。

升级保留 version=1 数据结构，新增字段均有兼容默认值，不自动导入旧 fish-memory 数据、不自动改写现有摘要。词典为本地只读资源，不进入上下文；授权见 lib/lexicon-NOTICE.txt。

验证使用隔离数据与模拟模型，未在正式 QQ 会话调用模型。模型的主观提炼质量仍需按实际会话检验。

## 0.3.4：崩溃残留锁与写入互斥

保留旧进程退出后的自动锁回收，仅 ESRCH 确认进程不存在时允许回收。同进程重复加载、活进程、权限不足、未知探测错误、缺失或损坏的锁信息一律拒绝接管。短期 .acquiring 文件串行化多个进程的获取和回收操作。每个实例有独立所有权 token，丢失所有权后拒绝写入，关闭时不删除其他实例的锁。

普通运行中崩溃留下的有效 writer.lock 可自动恢复。如果恰好在获取锁的短暂步骤内崩溃、留下 .acquiring，或锁内容损坏，需要先确认全部相关实例已停止，再检查该文件；插件不会自动猜测并删除。数据格式与既有来源、人物和范围保持兼容。
